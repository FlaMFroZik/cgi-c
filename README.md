# cgi-c

Небольшой многопоточный HTTP-сервер на C. Он **импортирует вашу CGI-функцию** из
динамической библиотеки (`.so`) через указатели на функции и вызывает её для каждого
запроса в рабочем потоке. Функция получает корневую папку — `char *root`, буфер на
**256 символов**, — и **«голые» данные от клиента**: запрос ровно в том виде, в каком
он пришёл из сокета.

```
браузер ──▶ socket.c ──▶ thread.c ──▶ import.c ──▶ cgi_main() из вашей .so
   ▲        принять      поток        вызов по          │
   │        соединение   из пула      указателю         │
   └──────────────── HTTP-ответ прямо в сокет ──────────┘
```

## Возможности

- Три модуля: `socket` (управляющий), `import` (импорт CGI), `thread` (потоки).
- CGI подключается во время работы: `dlopen()` + `dlsym()` → указатель на функцию
  типа `cgi_function_t`. Пересобирать сервер ради новой CGI не нужно.
- Пул рабочих потоков с очередью соединений; если очередь переполнена — `503`.
- Запрос передаётся CGI нетронутым, байт в байт (строка запроса, заголовки, тело), вместе
  с точным размером — подходят и двоичные данные с нулевыми байтами.
- Защита от медленных и зависших клиентов: общий срок на получение запроса, таймауты
  сокета, лимит размера запроса.
- `Expect: 100-continue`, аккуратное закрытие соединения (без RST), IPv4 и IPv6.
- Мягкая остановка по Ctrl+C: текущие запросы дорабатывают, затем CGI выгружается.
- Пример CGI, в котором CGI-функция и `main()` лежат в одном файле: он собирается и как
  `.so` для сервера, и как программа для проверки CGI без сервера.
- Только POSIX и стандартная библиотека C, без внешних зависимостей; сборка — `make`.

| Файл             | Что это                                                      |
|------------------|--------------------------------------------------------------|
| `cgi-server`     | сервер                                                       |
| `example/cgi.so` | пример CGI как библиотека — её импортирует сервер            |
| `example/cgi`    | тот же пример как обычная программа (работает его `main()`)  |

## Сборка и запуск

Нужны компилятор C (gcc или clang), `make` и POSIX-система. Проверено на Linux
(Debian 12, GCC 12, glibc 2.36). Код написан на POSIX, поэтому должен собираться и на
macOS / *BSD, но там не проверялся.

```sh
make          # собрать сервер и пример
make run      # собрать и запустить: ./cgi-server -p 8080 -r . -l ./example/cgi.so
```

Откройте <http://localhost:8080/> — там страница, которую собрала CGI-функция из примера.

| Команда        | Что делает                                                        |
|----------------|-------------------------------------------------------------------|
| `make`         | собрать всё: `cgi-server`, `example/cgi.so`, `example/cgi`        |
| `make server`  | только сервер                                                     |
| `make example` | только пример CGI                                                 |
| `make run`     | собрать и запустить с примером; можно `make run PORT=9000 ROOT=/var/www` |
| `make clean`   | удалить всё собранное                                             |

Отладочная сборка с AddressSanitizer:

```sh
make clean
make CFLAGS="-O0 -g -fsanitize=address,undefined" LDFLAGS="-fsanitize=address,undefined"
```

### Ключи сервера

```
./cgi-server [-p PORT] [-a ADDR] [-r ROOT] [-l LIB] [-f NAME] [-t N] [-m BYTES] [-T SEC] [-q] [-h]
```

| Ключ       | По умолчанию       | Значение |
|------------|--------------------|----------|
| `-p PORT`  | `8080`             | порт |
| `-a ADDR`  | `0.0.0.0`          | адрес для прослушивания: `0.0.0.0` — все интерфейсы, `127.0.0.1` — только этот компьютер, `::` — IPv6 и IPv4 сразу |
| `-r ROOT`  | `.`                | корневая папка. Сервер превращает её в абсолютный путь (не длиннее 255 символов) и передаёт в CGI как `root` |
| `-l LIB`   | `./example/cgi.so` | CGI-библиотека, из которой импортируется функция |
| `-f NAME`  | `cgi_main`         | имя CGI-функции в библиотеке |
| `-t N`     | `16`               | число рабочих потоков (1–1024) |
| `-m BYTES` | `1048576`          | максимальный размер запроса (заголовки + тело), от 1024 байт до 1 ГиБ |
| `-T SEC`   | `10`               | таймаут: за сколько секунд клиент должен прислать весь запрос; он же — таймаут чтения и записи сокета (1–3600) |
| `-q`       |                    | не печатать журнал запросов |
| `-h`       |                    | справка |

```sh
./cgi-server                                   # всё по умолчанию
./cgi-server -p 9000 -r /var/www -l ./my.so    # свой порт, корень и CGI
./cgi-server -l ./my.so -f handle_request      # CGI-функция с другим именем
./cgi-server -a 127.0.0.1 -t 4 -T 5 -q         # только локально, 4 потока, без журнала
```

При запуске сервер сообщает, что импортировал, а затем пишет по строке на каждый запрос:

```
cgi-server: CGI-функция cgi_main() импортирована из ./example/cgi.so
cgi-server: root = /home/user/cgi-c
cgi-server: рабочих потоков: 16, слушаю 0.0.0.0, порт 8080
cgi-server: откройте http://localhost:8080/  (Ctrl+C — остановка)
[2026-10-14 11:34:09] 127.0.0.1 "GET / HTTP/1.1" 200 0.1 ms
[2026-10-14 11:34:09] 127.0.0.1 "POST / HTTP/1.1" 200 0.1 ms
[2026-10-14 11:34:09] 127.0.0.1 "GET /nope.txt HTTP/1.1" 404 0.1 ms
```

Код в журнале — то, что вернула CGI-функция (или код ошибки, которую сервер отправил сам).

**Остановка.** По Ctrl+C (или `kill`) сервер перестаёт принимать соединения, дожидается
текущих запросов, выгружает CGI-библиотеку и выходит. Повторный Ctrl+C — выход немедленно.

Проверка из терминала:

```sh
curl http://localhost:8080/echo                            # сырые данные своего запроса
curl --data-urlencode 'name=Мир' http://localhost:8080/    # POST с полем формы
curl -I http://localhost:8080/                             # HEAD
printf 'GET /echo HTTP/1.1\r\nHost: x\r\n\r\n' | nc localhost 8080
```

## CGI-функция

### Сигнатура

Тип CGI-функции объявлен в `import.h`:

```c
#define CGI_ROOT_SIZE     256         /* размер буфера root, включая '\0' */
#define CGI_FUNCTION_NAME "cgi_main"  /* имя функции по умолчанию (ключ -f) */

typedef int (*cgi_function_t)(char *root, char *data, size_t size, int client);
```

Значит, ваша функция должна выглядеть так:

```c
int cgi_main(char *root, char *data, size_t size, int client);
```

### Аргументы

Два главных аргумента — **`root`** (256 символов) и **«голые» данные от клиента**
(`data`). Ещё два технически необходимы: `size` — чтобы данные были действительно
«голыми» (с любыми байтами, включая нулевые), и `client` — чтобы было куда отправить ответ.

| Аргумент | Тип      | Что в нём |
|----------|----------|-----------|
| `root`   | `char *` | **Корневая папка — буфер ровно на 256 символов** (`CGI_ROOT_SIZE`, то есть `char[256]`). В нём абсолютный путь к папке из ключа `-r`, например `/var/www` (без `/` в конце). Строка всегда заканчивается `'\0'`, поэтому сам путь не длиннее 255 символов — с более длинным сервер не запустится. У каждого запроса своя копия буфера: её можно менять, другим потокам это не помешает. |
| `data`   | `char *` | **«Голые» данные от клиента**: запрос в точности так, как он пришёл из сокета, — строка запроса, заголовки, пустая строка и тело. Сервер его не разбирает и не меняет. Для удобства после последнего байта дописан `'\0'`, так что текстовый запрос можно обрабатывать как строку. Буфер можно менять (например, разбирать «на месте»), но нельзя освобождать и нельзя хранить после возврата из функции. |
| `size`   | `size_t` | Сколько байт в `data` (без дописанного `'\0'`). Нужен потому, что в теле запроса могут быть нулевые байты (файлы, двоичные данные), а `strlen()` остановится на первом из них. |
| `client` | `int`    | Сокет клиента. В него CGI пишет **полный HTTP-ответ**: строку статуса, заголовки, пустую строку и тело (`write()`, `send()`, `dprintf()`...). Закрывать сокет не нужно — это сделает сервер. |

### Возвращаемое значение

| Значение          | Что значит |
|-------------------|------------|
| `200`, `404`, ... | HTTP-код отправленного ответа — сервер запишет его в журнал |
| `0`               | ответ отправлен, код не важен (в журнале будет `-`) |
| меньше нуля       | ответ **не** отправлен — сервер сам ответит `500 Internal Server Error`. Возвращайте отрицательное значение, только если ещё ничего не записали в `client` |

### Что приходит в `data`

Например, для формы, отправленной методом POST, CGI получит такие байты (`\r\n` — это два
байта, CR и LF):

```
POST /form HTTP/1.1\r\n
Host: localhost:8080\r\n
User-Agent: curl/7.88.1\r\n
Content-Type: application/x-www-form-urlencoded\r\n
Content-Length: 27\r\n
\r\n
name=%D0%9C%D0%B8%D1%80&x=1
```

`size` — общее число байт: заголовки плюс тело. Сервер дочитывает запрос целиком:
заголовки до пустой строки и ровно `Content-Length` байт тела. Если клиент прислал данные
без пустой строки в конце и закрыл передачу, CGI получит их как есть.

### Что CGI отправляет в `client`

Полный ответ HTTP/1.1:

```
HTTP/1.1 200 OK\r\n
Content-Type: text/html; charset=utf-8\r\n
Content-Length: 13\r\n
Connection: close\r\n
\r\n
<h1>Hi!</h1>\n
```

Сервер обрабатывает по одному запросу на соединение и закрывает его, когда CGI-функция
вернёт управление, поэтому указывайте `Connection: close`. `Content-Length` не обязателен
(клиент поймёт, что ответ закончился, когда закроется соединение), но с ним лучше: клиент
точно знает, что получил ответ целиком.

### Правила для CGI-функции

CGI работает **внутри процесса сервера** и одновременно в нескольких потоках. Поэтому:

1. **Потокобезопасность.** Функцию вызывают сразу несколько потоков. Не используйте
   глобальные и `static` переменные без мьютекса, а также непотокобезопасные функции:
   вместо `strtok`, `localtime`, `rand` — `strtok_r`, `localtime_r`, `rand_r`.
2. **Не завершайте процесс**: никаких `exit()` и `abort()`. Падение CGI (например,
   segfault) останавливает весь сервер.
3. **Не меняйте общее состояние процесса**: `chdir()`, `signal()`, `setlocale()` и т. п.
   Пути стройте от `root`: `snprintf(path, sizeof path, "%s/index.html", root)`.
4. **Не закрывайте `client` и не освобождайте `data`** — это делает сервер.
5. **Освобождайте свою память**: сервер работает долго, утечки накапливаются.
6. **Не задерживайтесь надолго**: пока работает CGI, её поток занят. На сокете стоят
   таймауты (`-T`), так что запись зависшему клиенту не будет ждать вечно, но бесконечный
   цикл в CGI займёт поток навсегда.
7. **Проверяйте пути из запроса**: путь вида `/../../etc/passwd` не должен выводить за
   пределы `root` (см. `path_is_safe()` и `realpath()` в примере).
8. Запись в сокет, который клиент уже закрыл, просто вернёт ошибку `EPIPE`: сигнал
   `SIGPIPE` сервер игнорирует, так что процесс не упадёт.

## Как написать свою CGI

**1.** Создайте файл, например `mycgi/main.c`, подключите `import.h` и напишите функцию:

```c
#include <stdio.h>
#include "import.h"   /* CGI_ROOT_SIZE и тип cgi_function_t */

int cgi_main(char *root, char *data, size_t size, int client)
{
    char body[512];
    int  len = snprintf(body, sizeof body,
                        "Привет из CGI!\nroot = %s\nполучено байт: %zu\n", root, size);

    dprintf(client,
            "HTTP/1.1 200 OK\r\n"
            "Content-Type: text/plain; charset=utf-8\r\n"
            "Content-Length: %d\r\n"
            "Connection: close\r\n"
            "\r\n"
            "%s", len, body);
    (void)data;
    return 200; /* код ответа — для журнала сервера */
}
```

**2.** Соберите её как динамическую библиотеку (`-I` — путь к папке с `import.h`):

```sh
gcc -Wall -Wextra -shared -fPIC -I /путь/к/cgi-c -o mycgi.so mycgi/main.c
```

`-shared` собирает `.so` вместо программы, `-fPIC` — позиционно-независимый код, без
которого разделяемую библиотеку не собрать.

**3.** Запустите сервер с ней:

```sh
./cgi-server -l ./mycgi.so -r /var/www
curl http://localhost:8080/
```

Если функция называется иначе, укажите имя: `-f my_function`. Функция должна быть видна
снаружи библиотеки, то есть не `static`. Если CGI написана на C++, объявите функцию как
`extern "C"`, иначе компилятор изменит её имя и `dlsym()` её не найдёт.

## Пример: example/main.c

В одном файле лежат **CGI-функция `cgi_main()` и функция `main()`**. Makefile собирает его
дважды:

```sh
cc ... -fPIC -shared -o example/cgi.so example/main.c   # библиотека: сервер импортирует cgi_main
cc ...               -o example/cgi    example/main.c   # программа: работает main()
```

В библиотеке `main()` просто не используется: сервер берёт из неё только `cgi_main`. А в
программе `main()` делает то же, что сервер для одного запроса: заполняет буфер
`root[256]`, читает «голые» данные (здесь — из stdin) и вызывает CGI-функцию через
указатель `cgi_function_t`, передав вместо сокета `stdout`. Так CGI удобно отлаживать без
сервера:

```sh
printf 'GET /echo HTTP/1.1\r\nHost: x\r\n\r\n' | ./example/cgi .
printf 'GET / HTTP/1.1\r\n\r\n' | ./example/cgi /var/www > page.html
```

Что отвечает пример:

| Запрос      | Ответ |
|-------------|-------|
| `GET /`     | HTML-страница: значения аргументов CGI-функции (`root`, `size`, `client`), разбор первой строки запроса, сырые данные с видимыми `\r\n`, форма для POST, список файлов в `root` |
| `POST /`    | та же страница плюс поля отправленной формы (`application/x-www-form-urlencoded`) |
| `* /echo`   | сырые данные запроса обратно, как `text/plain` |
| `GET /путь` | файл из `root` (тип — по расширению) или список файлов, если это папка; `404`, если файла нет |
| `HEAD ...`  | то же, но без тела |
| остальное   | `400`, `403` (выход за пределы `root`, скрытые файлы), `405`, `414` |

На нём видны типичные приёмы: разбор первой строки и заголовков из «голых» данных,
раскодирование `%XX`, построение пути от `root` с защитой от `..` и символических ссылок,
отправка ответа целиком (`send_all()`), возврат `-1` при нехватке памяти (тогда сервер
сам ответит 500). Функция не использует глобальных переменных, поэтому безопасна для
вызова из нескольких потоков сразу.

## Как устроен сервер

### Путь одного запроса

```
  клиент
    │ TCP
    ▼
┌─ главный поток: socket.c ─────────────────────────────┐
│ poll() + accept()  →  thread_pool_push(client)        │
└───────────────────────────┬───────────────────────────┘
                            │ очередь сокетов
                            ▼
┌─ рабочий поток: thread.c ─────────────────────────────┐
│ thread_worker() берёт сокет из очереди и вызывает     │
│ pool->task(client, arg)    ← указатель thread_task_t  │
└───────────────────────────┬───────────────────────────┘
                            ▼
┌─ socket_client(): socket.c, в том же рабочем потоке ──┐
│ 1. socket_read_request() → data, size: «голые» данные │
│ 2. memcpy(root, server->root, 256): своя копия root   │
│ 3. import_call() → cgi->function(root, data, size,    │
│                                  client) ← import.c   │
│ 4. журнал, free(data), socket_close(client)           │
└───────────────────────────┬───────────────────────────┘
                            ▼
          cgi_main() из .so пишет ответ в client
```

### socket.c / socket.h — управляющий модуль

`socket.c` содержит `main()` и связывает остальные модули. Порядок работы:

1. Разбор ключей (`getopt()`).
2. `set_root()` — `realpath()` превращает `-r` в абсолютный путь и кладёт его в `char root[256]`.
3. `import_library()` — импорт CGI-функции (см. ниже).
4. `setup_signals()` — Ctrl+C и `SIGTERM` выставляют флаг остановки; `SIGPIPE` игнорируется.
5. `socket_listen()` — `getaddrinfo()` → `socket()` → `bind()` → `listen()`.
6. `thread_pool_create()` — запуск рабочих потоков; им передаётся указатель на
   обработчик `socket_client()` и указатель на настройки сервера.
7. `accept_loop()` — `poll()` + `accept()`, каждое соединение — в очередь пула; если
   очередь полна, клиент сразу получает `503`.
8. Остановка: закрыть слушающий сокет → `thread_pool_destroy()` (дождаться потоков) →
   `import_close()` (выгрузить CGI).

Функции из `socket.h`:

| Функция | Что делает |
|---------|------------|
| `int socket_listen(const char *address, const char *port)` | открывает слушающий TCP-сокет (IPv4 или IPv6) |
| `int socket_read_request(int client, size_t max_size, int timeout_ms, char **data, size_t *size)` | читает запрос целиком и возвращает «голые» данные. `0` — успех, `>0` — HTTP-код ошибки для клиента, `-1` — клиент ушёл или ничего не прислал |
| `void socket_send_status(int client, int code)` | короткий ответ с кодом (для ошибок) |
| `void socket_close(int client, int linger)` | закрывает соединение аккуратно: `shutdown()` и дочитывание остатков, чтобы ядро не отправило RST и клиент не потерял ответ |

Как сервер читает запрос: порциями, пока не придёт пустая строка (конец заголовков). Из
заголовков он смотрит только на `Content-Length`, `Transfer-Encoding` и `Expect`, а затем
дочитывает ровно `Content-Length` байт тела. Весь запрос должен прийти за `-T` секунд — это
общий срок, а не таймаут каждого `recv()`, поэтому медленный клиент не займёт поток надолго.

Ответы, которые сервер отправляет сам (CGI в этих случаях не вызывается или не ответила):

| Код | Когда |
|-----|-------|
| `400 Bad Request` | испорченный или противоречивый `Content-Length`; тело оборвалось раньше, чем обещал `Content-Length` |
| `408 Request Timeout` | клиент не прислал запрос целиком за `-T` секунд |
| `411 Length Required` | тело в `Transfer-Encoding: chunked` — серверу нужен `Content-Length` |
| `413 Content Too Large` | запрос больше `-m` байт |
| `431 Request Header Fields Too Large` | одни только заголовки больше `-m` байт |
| `500 Internal Server Error` | CGI-функция вернула отрицательное значение |
| `503 Service Unavailable` | все потоки заняты и очередь (256 соединений) заполнена |

Кроме того, на `Expect: 100-continue` (так делает curl перед большим телом) сервер
отвечает промежуточным `100 Continue`, чтобы клиент не ждал зря.

### import.c / import.h — импорт CGI через указатели на функции

`cgi_function_t` — это тип «указатель на функцию, которая принимает
`(char *, char *, size_t, int)` и возвращает `int`». Импортированная CGI хранится в структуре:

```c
typedef struct {
    void          *library;   /* дескриптор библиотеки — результат dlopen() */
    cgi_function_t function;  /* указатель на CGI-функцию — результат dlsym() */
} cgi_import_t;
```

| Функция | Что делает |
|---------|------------|
| `int import_library(cgi_import_t *cgi, const char *path, const char *name)` | загружает библиотеку и находит в ней функцию по имени. `0` — успех, `-1` — ошибка (причина печатается в stderr) |
| `int import_call(const cgi_import_t *cgi, char *root, char *data, size_t size, int client)` | вызывает CGI-функцию через указатель |
| `void import_close(cgi_import_t *cgi)` | выгружает библиотеку; вызывать, только когда CGI уже никто не выполняет |

Что происходит внутри, по шагам:

```c
void *library = dlopen("./example/cgi.so", RTLD_NOW | RTLD_LOCAL); /* 1. загрузить .so      */
void *symbol  = dlsym(library, "cgi_main");                        /* 2. найти адрес        */
memcpy(&cgi->function, &symbol, sizeof cgi->function);             /* 3. void* -> указатель */
int code = cgi->function(root, data, size, client);                /* 4. вызов по указателю */
dlclose(library);                                                  /* 5. выгрузить          */
```

Тонкости:

- `dlsym()` возвращает `void *`. Стандарт C не описывает превращение `void *` в указатель на
  функцию, но POSIX требует, чтобы оно работало; копирование через `memcpy()` — переносимый
  способ без предупреждений компилятора. `_Static_assert` проверяет, что размеры указателей
  совпадают.
- `RTLD_NOW` разрешает все символы библиотеки сразу: если CGI ссылается на несуществующую
  функцию, ошибка будет видна при запуске сервера, а не посреди запроса.
- Путь без `/` (`-l cgi.so`) `dlopen()` искал бы в системных папках, как компоновщик ищет
  `-lfoo`, поэтому `import_library()` превращает его в `./cgi.so`.
- Библиотеку выгружают только после остановки всех потоков: `dlclose()` в момент, когда
  какой-то поток ещё выполняет код CGI, привёл бы к падению.

### thread.c / thread.h — пул потоков

Работа разделена между потоками: главный поток только принимает соединения, а
обрабатывают их `N` рабочих потоков (ключ `-t`). Между ними — очередь (кольцевой буфер
сокетов), защищённая мьютексом, и условная переменная, на которой свободные потоки ждут
работу.

| Функция | Что делает |
|---------|------------|
| `thread_pool_t *thread_pool_create(size_t threads, size_t queue_size, thread_task_t task, void *arg)` | запускает потоки; каждый будет вызывать `task(client, arg)` для очередного соединения |
| `int thread_pool_push(thread_pool_t *pool, int client)` | кладёт сокет в очередь; `-1`, если очередь полна |
| `void thread_pool_destroy(thread_pool_t *pool)` | останавливает пул: потоки дообслуживают очередь и завершаются |

Обработчик тоже передаётся указателем на функцию:

```c
typedef void (*thread_task_t)(int client, void *arg);
```

Пул ничего не знает о HTTP и CGI — он просто вызывает `pool->task(client, pool->arg)`.
В сервере это `socket_client()` из `socket.c`, а `arg` — указатель на настройки сервера
(`root`, импортированная CGI, лимиты).

Сигналы `SIGINT` и `SIGTERM` в рабочих потоках заблокированы, поэтому Ctrl+C всегда
получает главный поток: он сразу выходит из `poll()` и начинает остановку.

## Ограничения

- Одно соединение — один запрос (`Connection: close`), keep-alive нет.
- Тело запроса — только с `Content-Length`; на `Transfer-Encoding: chunked` сервер отвечает `411`.
- Нет HTTPS. Если он нужен, поставьте перед сервером nginx или caddy.
- CGI выполняется в процессе сервера: её падение или `exit()` останавливает весь сервер,
  а бесконечный цикл навсегда занимает поток.
- Запрос целиком хранится в памяти (до `-m` байт на каждый поток).
- Чтобы заменить CGI, сервер нужно перезапустить.
